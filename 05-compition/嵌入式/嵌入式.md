# 嵌入式

## 理论部分

### MCU 选型

> [!quote] 一个原则：花最少的钱，做最多的事

在确定项目需求的情况下，一般按照下面的顺序选择合适的 MCU：

1. **选内核** — 选择哪种内核的芯片。内核越高，意味着功耗也越高
2. **选引脚** — 选择多少引脚的芯片。引脚数量决定了资源（外设）的多少，也影响价格
3. **选存储** — 选择多大 RAM 和 FLASH 的芯片。FLASH 越大，价格越贵
4. **选供货** — 还要考虑所选型号是否采购容易、供货是否稳定

### 芯片基础概念

- 存储器映射
- 寄存器
- 总线
- 数据手册（选型 / 开发时查阅）

### 支持的 4 种驱动库

| 驱动库 | 说明 | 优缺点 |
| --- | --- | --- |
| **基于寄存器编程** | 直接操作寄存器 | 最底层，效率最高，但开发慢 |
| **SPL**（标准外设库） | ST 官方早期标准库 | 封装适中，已逐渐被 HAL 取代 |
| **HAL**（封装 + 抽象） | 配合 CubeMX 生成代码 | 可阅读、可封装、硬件覆盖广；**运行效率较差** |
| **LL**（Low Layer，更少抽象） | 轻量底层库 | 适合**频繁 IO** 操作 |

> [!note] 实际开发中的选择
> - 现代开发更喜欢用 **HAL（配合 CubeMX）** 和 **LL**
> - 遗留问题：AI 开发常常**不经过 HAL**、直接修改代码 —— 那它实际使用的是哪种库？属于寄存器直接操作，还是 LL？
