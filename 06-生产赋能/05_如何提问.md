# 如何提问

> 来源：《提问的智慧》How To Ask Questions The Smart Way — Eric S. Raymond / Rick Moen
> [中文版](https://github.com/ryanhanwu/How-To-Ask-Questions-The-Smart-Way/blob/main/README-zh_CN.md) ｜ [英文版](http://www.catb.org/~esr/faqs/smart-questions.html)

## 总结

一句话：**别当伸手党，提问的本质是"用我的思考，换别人的时间"。**

- 好问题是厚礼，回答者会感激；蠢问题是索取，只会被无视。
- 回答者都是自愿抽出时间的忙人，只愿意帮**先自救过**的人。
- 核心公式 = 说明我已做的功课 + 给出完整环境与症状 + 明确需要的帮助。

## 提问前（先做功课）

按顺序尝试，找不到再问：

1. 搜论坛旧帖、Google、手册、FAQ
2. 自己检查、做实验复现
3. 问身边的高手；开发者还可以读源码
4. 提问时**主动表明做过以上努力**，并说出你学到了什么

> ✅ `我用 Google 搜过 "xxx 报错"，没找到有用的。`
> ✅ `我读了 FAQ，但里面没提到 Nulix 相关的问题。`

⚠️ 别问错问题：基于错误假设的问题，只会得到无意义的字面回答。

## 提问时

### 选对场合
- 找对论坛/频道，初级问题别发到进阶版
- 别跨平台重复发帖、别私信陌生人
- 先搜论坛历史，感受氛围再发

### 标题（50 字内）
- 用 `目标 —— 差异` 格式
- ❌ 救命啊！电脑不能显示了！
- ✅ X.org 6.8.1 鼠标指针在某牌显卡 MV1005 芯片组下变形
- 别写"帮帮忙/跪求/急/紧急"

### 表达
- 语句清晰准确，别用火星文，别全大写
- 用纯文本，别发 Word/Excel 附件
- 明确需求：`我想更好地理解 X，可否指点一下哪有好说明？` 优于 `你能解释一下 X 吗？`

### 描述问题
- **描述症状而非猜测** —— 回答者要"看证据"，不是听你的推断
- **按时间先后列操作步骤**，长文先写概述再展开
- **描述目标而非过程** —— 说清想达到什么，而不是卡在哪个动作上
- 给出环境：系统、版本、配置、最近改动
- 提供可复现的最小案例

### 代码问题
- 贴最小可复现用例（几十行），别贴几百行说"它不工作"
- 写明期待 vs 实际：`第 7 行后我期待 <x>，实际是 <y>`
- 求 review 时说明重点关注的代码段及原因

### 心态
- 别动辄声称"找到 Bug"——除非能给出补丁或回归测试
- 别低声下气（"我只是个可悲的新手…"），描述事实即可
- 结尾别加"有人能帮我吗？"，避免是非型问句
- 彬彬有礼、多用"请/谢谢"，但礼貌替代不了功课

### 问题解决后
- 回复原帖，标题标注 `已解决`，简短说明解决方式
- 感谢帮助过你的人（别只说"先谢了"）
- 值得的话把结论整理成 FAQ 回馈社区 —— 这是积累声誉的方式

## 解读答案

- 收到 **RTFM / STFW** = 答案很容易找到，自己搜比被喂更有益，不必生气
- 看不懂回应：先自己查，别急着要解释；追问也要先说明自己查过什么
- 被无礼回应：多数是"直截了当"的风格，不是冒犯；真正的人身攻击才值得反击，且必须有根据

## 不该问的问题（反例）

| 蠢问题 | 为什么蠢 |
|---|---|
| 我能在哪找到 X？ | 搜索引擎那头就有 |
| 我怎样用 X 做 Y？ | 只问方法，不问目标 |
| 我的程序/设定/SQL 没有用 | 信息为零，无从答起 |
| 我的 Windows 有问题，你能帮我吗？ | 太宽泛 |
| 我认为系统工具 X 有问题 | 拿不出证据的断言 |

## 好问题示例（可直接套用）

**蠢**：我从 foo 项目找来的源码没法编译。它怎么这么烂？
**好**：foo 项目代码在 Nulix 6.2 下编译不过。我读过了 FAQ，但没提到 Nulix 相关问题。这是我编译过程的记录，我有什么做的不对的地方吗？

**蠢**：我的主机板有问题了，谁来帮我？
**好**：我在 S2464 主机板上试了 X、Y、Z 没用，又试了 A、B、C。尝试 C 时有奇怪现象……有谁知道接下来我该做什么测试？

关键区别：`告诉我答案` vs `给我启示、指出我还该做什么诊断`。

## 如果得不到回答

- 不是被忽视，可能只是对方不知道答案 / 时区不同
- 别重复发帖，耐心等待，或换更适合新手的渠道
- 付费求助不可耻（免费软件 ≠ 免费支持）

## 如果我回答别人

- 态度和善，对新手私下纠错，别当众羞辱
- 不确定就直说，别装权威
- 给方向/链接，而不是甩一句 RTFM 完事
- 授人以渔：展示思路，而不是直接端出结果
- 把好问题沉淀成文档/FAQ，让社区受益
