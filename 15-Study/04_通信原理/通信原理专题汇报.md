| 层级          | 负载特征                      | 主要硬件需求                         | 配置建议                                   |

| 语谱图实时分类     | 瀑布图切块、CNN 实时推理            | GPU 推理性能、CPU 预处理能力             | NVIDIA GPU，8 GB 及以上显存                  |

| 全天频谱存档分析    | 长时间 I/Q 记录、时序异常检测、批量分析    | 大容量存储、内存带宽、数据读写速度              | 1–2 TB NVMe SSD，必要时扩展 HDD，32–64 GB 内存  |
| 监测报告 LLM    | 32B–70B 量化推理、RAG 检索       | GPU 显存、内存、存储                   | 32B 级考虑 24 GB 显存；70B 级通常需要 48 GB 或多卡部署 |

总体结论： SDR 实时处理以 CPU 和数据传输能力为核心；AI 频谱认知以 GPU 算力和显存为核心；长期监测分析则更加依赖内存与存储容量。


# 微信公众号的项目路线
可以。对于课程项目，我建议不要尝试把前面那套“专业频谱监测站”完整搬到个人笔记本电脑上，而是保留核心技术路线，缩小硬件规模和模型复杂度，用一台笔记本电脑 + 一台 ADALM-Pluto（PlutoSDR）搭建一个轻量级 AI 频谱监测系统。

### 一、课程项目的目标架构

硬件层：ADALM-Pluto

采样、滤波、FFT、瀑布图、能量检测、CFAR

AI 认知层：PyTorch

语谱图分类、调制识别、频谱目标检测

展示层：Python GUI / SDRangel

频谱显示、识别结果、检测记录与报告

建议把项目定位为：

基于 PlutoSDR 的轻量级 AI 无线电频谱感知系统。

它既能展示通信原理和 SDR 技术，也能体现 AI 与通信交叉的特点。

### 二、硬件选择：Pluto 足以支撑课程项目

### 三、软件选择：从原来的全栈缩减为五个核心工具

| 层级       | 原方案                  | 课程项目建议                   | 选择理由                 |
| -------- | -------------------- | ------------------------ | -------------------- |
| 硬件驱动     | 多种 SDR 驱动            | libiio + pyadi-iio       | 直接控制 Pluto、获取 I/Q 数据 |
| SDR 信号处理 | SDRangel + GNU Radio | GNU Radio 或 Python 二选一为主 | 完成采集、滤波、FFT、解调       |
| 数据处理     | SigMF + Python       | NumPy + SciPy + SigMF    | 数据保存、频谱计算、离线分析       |
| AI 认知    | PyTorch + YOLO       | PyTorch + CNN            | 实现调制识别或频谱分类          |
| 结果展示     | Grafana + Prometheus | Matplotlib + Streamlit   | 展示瀑布图、检测结果和统计信息      |

我更建议采用 Python 为主的路线：

* `pyadi-iio`：控制 Pluto 和读取 I/Q 数据。

* `NumPy/SciPy`：信号处理。

* `Matplotlib`：绘制频谱和瀑布图。

* `PyTorch`：训练与推理。

* `Streamlit`：制作课程演示界面。

ADI 官方提供了 pyadi-iio 接口示例，也提供 GNU Radio 的 Pluto 接入方案。GNU Radio 3.10 及以上版本已包含 gr-iio 支持。System Level Documentation documentation +1

### 四、项目实施：分四个阶段复刻

建议把项目拆成四个可独立验收的模块，每个阶段都产生实际成果。

* 阶段一：Pluto 硬件接入与 I/Q 采集

    * 安装 libiio、pyadi-iio。

    * 识别 Pluto，读取 I/Q 数据。

    * 绘制时域波形、FFT 频谱。

    * 保存 I/Q 数据文件。

    验收成果：硬件采集与频谱显示

* 阶段二：传统 DSP 频谱监测

    * 实现 DDC、FIR 滤波和抽取。

    * 实现 FFT 和瀑布图。

    * 实现能量检测与 CFAR。

    * 统计频谱占用情况。

    验收成果：基础频谱监测系统

* 阶段三：AI 信号识别

    * 使用 Python 生成 BPSK、QPSK、2FSK、16QAM 等仿真信号。

    * 构建 I/Q 或语谱图数据集。

    * 使用 PyTorch 训练 CNN。

    * 比较不同信噪比下的识别准确率。

    验收成果：AI 调制识别模型

* 阶段四：系统集成与可视化

    * 将 Pluto 实时采集接入 DSP 流程。

    * 将检测结果送入 AI 模型。

    * 使用 Streamlit 展示频谱、瀑布图和识别结果。

    * 保存检测记录并生成简单统计报告。

    验收成果：端到端 AI 频谱感知系统

其中，第三阶段建议先用仿真数据训练，再用 Pluto 获取的实际数据进行测试。这样可以把算法问题与硬件采集问题分开排查。

### 六、课程项目的范围控制

我建议不要一开始就做 YOLO、RAG、LLM 和全天候监测。对于个人课程项目，优先级如下：

| 功能                   | 优先级  | 是否建议完成 |
| -------------------- | ---- | ------ |
| Pluto 实时 I/Q 采集      | 必须   |        |
| FFT、瀑布图              | 必须   |        |
| 能量检测、CFAR            | 必须   |        |
| CNN 调制识别             | 必须   |        |
| 实时识别与可视化             | 推荐   |        |
| YOLO 频谱目标检测          | 可选   |        |
| LLM + RAG 报告         | 可选   |        |
| Prometheus + Grafana | 暂不需要 |        |

实际无线信号采集建议先以接收为主。若需要进行发射或收发闭环实验，应在教师指导下使用合规的实验环境和适当的射频隔离措施。

### 七、我认为最适合你的项目定位

项目名称：基于 PlutoSDR 与深度学习的智能无线电频谱感知系统

它包含三个有层次的研究问题：

* 传统方法： 如何通过能量检测和 CFAR 发现无线信号？

* AI 方法： 如何利用 CNN 识别不同调制方式？低信噪比下性能如何？

* 系统集成： 如何将 SDR 实时采集、DSP 处理和 AI 识别连接起来？

这三个问题分别对应通信原理、数字信号处理和人工智能，能够形成比较完整的课程项目逻辑。

一个关键建议： 把传统 DSP 作为基线，把 AI 作为改进方案。通过准确率、检测概率、虚警率、处理延迟等指标进行对比，而不是仅仅展示一个能够运行的 CNN。这样项目会更有研究价值，也更容易在答辩中体现技术深度。
