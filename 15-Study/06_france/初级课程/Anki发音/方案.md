## 1. 目标与结论

给 Obsidian Flashcards 生成的法语卡自动加发音，并且**不与 Flashcards 插件的同步机制冲突**。

结论：把发音写进新增的 `Audio` 字段，而不是写进 `Back`。这样 Flashcards 插件同步时只更新它管理的四个字段，`Audio` 不会被覆盖。

本次已经完成：

- 在 `Obsidian-basic` 模型里新增第 5 个字段 `Audio`。

- 原有 `Front`、`Back`、`Context`、`Source` 四个字段逐条比对，未发生改动。

## 3. Anki 里具体改了什么

### 3.1 新增字段

`Obsidian-basic` 的字段从：

```
Front, Back, Context, Source
```

变成：

```
Front, Back, Context, Source, Audio
```

### 3.2 背面模板

在原来的 `{{Back}}` 之后、`{{Source}}` 之前插入了：

```html
{{#Audio}}<div class="fc-audio">{{Audio}}</div>{{/Audio}}<!-- anki-audio -->
```

`{{#Audio}}...{{/Audio}}` 表示只有 Audio 字段非空时才显示播放器，所以 DSP、通信原理等同样使用 `Obsidian-basic` 的卡片不会多出空白区域。

### 3.3 卡片内容

每张卡的 `Audio` 字段形如：

```
[sound:fr_f1a87cd62d30.mp3]
```

音频文件存放在 Anki 的媒体库：

```
C:\Users\15198\AppData\Roaming\Anki2\2\collection.media\
```

## 4. 为什么不会和 Flashcards 插件冲突

当前插件是 `flashcards-obsidian` v2.2.0（Flashcards，作者 Alex Colucci）。它通过 AnkiConnect 同步，并在每篇笔记的 frontmatter 里记录 `nid`、`hash`、`sync`。

阅读其 `main.js` 后确认：

1. 建卡时只写 `Front`、`Back`、`Context`、`Source` 四个字段。
2. 更新时只调用 `updateNoteFields`，并且只传入这四个字段；读取现有笔记做比较时，`la()` 也**只取这四个字段**参与哈希。
3. 因此 `Audio` 字段对它来说不存在：不会被比较、不会被覆盖、也不会造成重复更新。
4. 正常同步（`Update Anki from current note` / `Update Anki from vault`）只在缺少 `Context` / `Source` 时补模板，不会重建整个模板，所以 `{{Audio}}` 会保留。

### 4.1 唯一需要避免的操作

**不要运行命令面板里的 `Apply v2 Anki card style`。**

这个命令会把四个 Obsidian 模板和 CSS 重置成官方样式，`{{Audio}}` 会被删掉。它是手动命令，正常同步不会触发。万一误按，重新运行一次本脚本即可把播放器加回来：

```bash
uv run --with edge-tts==7.3.1 python add_audio.py --apply
```

脚本的 `ensure_schema()` 会检查模板，缺了就补。

### 4.2 会丢音频的少数情况

下列情况插件会新建 note 再删除旧 note，新 note 的 `Audio` 为空，需要重跑脚本：

- 卡片类型改变（basic ↔ reversed ↔ cloze），并在弹窗里确认重建。
- Anki 里的 note 被手动删除后，插件按 Markdown 重新创建。
- 从 Markdown 删除卡片后又在别处重新添加。

以下情况不会丢音频：

- 只改 Markdown 里的文字：`Audio` 保留，但发音可能过期，重跑脚本会按新文本生成新文件。
- 改卡组：插件用 `changeDeck`，不重建 note。
- 插件以后新建的卡：`Audio` 为空，重跑脚本补上。

## 5. 日常使用

### 5.1 运行环境

系统自带的 `edge-tts` 是 7.2.7，会被微软接口拒绝（403）。必须用 7.3.1：

```bash
cd "E:\ob\-first\-first\15-Study\06_france\初级课程\Anki发音"
uv run --with edge-tts==7.3.1 python add_audio.py --dry-run
```

`uv` 会把 edge-tts 7.3.1 放进临时环境，不污染系统 Python。Anki 必须保持打开，AnkiConnect 监听 `127.0.0.1:8765`。

### 5.2 常用命令

```bash
# 也可以直接用快捷脚本（不带参数时是 dry-run）
run.bat
run.bat --apply

# 只看计划，不修改
uv run --with edge-tts==7.3.1 python add_audio.py --dry-run

# 批量生成/更新
uv run --with edge-tts==7.3.1 python add_audio.py --apply

# 只处理一张卡
uv run --with edge-tts==7.3.1 python add_audio.py --apply --note-id 1792841304500

# 只处理前 5 张
uv run --with edge-tts==7.3.1 python add_audio.py --apply --limit 5

# 强制重新生成（即使文件已存在）
uv run --with edge-tts==7.3.1 python add_audio.py --apply --force

# 换男声 / 换语速
uv run --with edge-tts==7.3.1 python add_audio.py --apply --voice fr-FR-HenriNeural --rate "-5%"
```

脚本是幂等的：已存在且文本哈希一致的卡会跳过，所以可以反复运行。

### 5.3 推荐的维护流程

1. 在 Obsidian 里修改法语笔记。
2. 用 Flashcards 的 `Update Anki from current note` 或 `Update Anki from vault` 同步到 Anki。
3. 运行 `add_audio.py --apply`。
4. 在 Anki 里复习，发音播放器在答案下方。

## 6. 文本是怎么提取的

优先级从高到低：

1. `Back` 里的 `<code>...</code>` 片段。
2. 如果第 1 步没有得到可读片段，提取 `Back` 的纯文本法语。
3. 如果还没有，提取 `Front` 里的 `<code>`。
4. 最后提取 `Front` 的纯文本。

过滤规则：

- 去掉中文、中文标点和 `⚠` 等符号。
- 跳过词尾/词干片段：`-ent`、`-iss-`、`-x`、`-s`、`vienn-`、`pouv-`、`peu-`、`t'` 等。
- 保留真实单词和句子，例如 `et`、`en`、`au`、`aux`、`veuve`、`quatre-vingts`。
- `marié(e)` 读作 `mariée`；`veuf (veuve)` 读作 `veuf, veuve`；`il/elle` 读作 `il, elle`。
- 多个片段按顺序用逗号连接，生成一段音频。

文件名：

```
fr_ + sha1(朗读文本)[:12] + .mp3
```

文本不变就复用同一个文件；文本变了文件名也会变，便于增量更新。

### 6.1 当前跳过的卡

`1792841304235`（Unit 2，讲 `-e, -es, -e, -ons, -ez, -ent` 词尾的卡）没有可读的法语词，全部是词尾片段，因此保持无音频。如果需要，可以手动在 `Audio` 字段里加一段，或把它改成完整的变位示例。

### 6.2 包含“错误形式”的卡

有些卡的解析结果会同时包含正确和错误形式，例如：

- `nous choisissons, nous choisisons`
- `cet ordinateur, ce ordinateur`
- `des yeux, des œils`

这是因为原卡片的 `<code>` 里同时放了两者。如果只想听正确形式，需要在 Markdown 里把错误形式移出 `<code>`，或者修改脚本的提取规则。

## 8. 常见问题

**Q：运行时报 403 `Invalid response status`。**

A：用了系统 Python 的 edge-tts 7.2.7。改用：

```bash
uv run --with edge-tts==7.3.1 python add_audio.py --apply
```

**Q：报 `无法连接 AnkiConnect`。**

A：Anki 没打开，或 AnkiConnect 没启用。确认 Anki 正在运行，且 `127.0.0.1:8765` 可访问。

**Q：卡片背面没有播放器。**

A：检查两件事：

1. 该卡的 `Audio` 字段是否为空。
2. `Obsidian-basic` 的背面模板是否还包含 `{{Audio}}`。如果被 `Apply v2 Anki card style` 重置了，重跑脚本即可。

**Q：Obsidian 同步后发音没了。**

A：发音应该不会没。如果 `Audio` 字段被清空，说明音频被写进了 `Front/Back/Context/Source` 之一，或者 note 被重建。检查 `Audio` 字段；重跑脚本。

**Q：想换音色。**

A：常用法语 edge-tts 音色：

- `fr-FR-DeniseNeural`（女声，当前使用）
- `fr-FR-HenriNeural`（男声）
- `fr-CA-SylvieNeural`（加拿大法语女声）

列出全部音色：

```bash
uv run --with edge-tts==7.3.1 edge-tts --list-voices | grep fr-
```

**Q：想每个短语单独一个播放器。**

A：当前是“每张卡一段”。如果改成每词一段，需要让脚本把多个 `[sound:]` 标签按顺序写进 `Audio` 字段（Anki 会依次播放），或者拆成多个字段。可以在此基础上改。

## 9. 与插件的边界（备查）

- 插件同步的四个字段：`Front`、`Back`、`Context`、`Source`。
- 插件不读、不写：`Audio`。
- 插件正常同步不重建模板；只有 `Apply v2 Anki card style` 会重置模板和 CSS。
- 插件会删除 Markdown 中已移除的卡片，对应的 Anki note 和音频引用会一起消失；媒体文件可能残留，可用 `检查媒体` 清理。
- 插件不会删除 `collection.media` 里的音频文件。

## 10. 已知限制

1. 一张卡只生成一段音频，不是逐词播放器。
2. 表格类卡片（如动词变位）会按表格顺序连读，例如“je parle tu parles il, elle parle…”，没有逐行停顿。
3. 文本提取基于规则，不理解语义；正确/错误形式同时出现时会一起读。
4. 词尾变化卡（如 `-ent` 不发音）无法生成有意义的音频，已跳过。
5. edge-tts 依赖微软在线接口；离线时无法生成新音频，但已生成的 mp3 不受影响。
